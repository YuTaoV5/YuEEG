# Rev H 姿态与短时相对轨迹

2026-11-01 用户已选择：**不部署基站，先实现姿态与短时相对轨迹**。本版不增加UWB、GNSS或磁力计。SCH16T-K01连续采样、相对解算与接收工具已实现并通过软件验证；尚未烧录实测，不提供位置精度或航向漂移保证。

## 坐标、对准和有效范围

输出采用厂家传感器的右手坐标系。固件四元数按 **w,x,y,z，将传感器坐标旋转到局部坐标**；局部Z朝上，初始yaw设为0。该零点是任意相对方向，不是北向、房间固定方向或已标定的头部方向。背面安装的芯片轴与主板轴不同，外壳到头部的安装变换还需标定。接收工具从四元数转换roll／pitch／相对yaw。

`imu align`／`imu zero` 均要求用户明确把设备保持静止。收集至少2秒、至少200个合格样本，检查陀螺均值／方差、加速度模长／方差及拒收比例，再估计陀螺零偏和重力方向，假设初速为零并建立新的坐标原点ID。单次静止对准不等于完整六面加速度或温度标定；恒速平移、缓慢匀转和某些持续加速度不能仅凭这些检查排除。因此不能在运动中用该命令“校正”出一个看似稳定的位置。

对准成功后，位置和速度只在**3秒工程窗口**内积分；期间用陀螺传播姿态，并将加速度旋转到局部坐标后减去标准重力9.80665m/s²。窗口内关闭加速度对倾角的反馈，防止把要测的线性加速度误当作姿态误差。窗口结束后姿态继续传播，并在模长／角速度门限内进行互补倾角修正；该门限不能证明此时只有重力。

3秒后速度／位置标为无效，线上对应字段为NaN；不会继续给出“有效”的无约束轨迹，也不自动执行零速更新。CRC、状态、跨样本、丢样或时序失锁会使解算失效，需再次静止对准。**3秒是功能窗口，不是经过测量的精度保证**。任意yaw、加速度零偏、重力投影误差和温漂仍会累积。

## 使用顺序

1. 用人体断开的台架验证硬件后，先发送 `stop`，再发 `imu start`。初始化仅允许在EEG停止时执行。
2. 等待 `imu status` 中的DRDY周期稳定，再发 `imu align` 并持续静止至少2秒。成功后状态包含 `attitude_valid`／`trajectory_valid`。
3. 在3秒窗口内观察短时相对运动；到期后姿态可继续输出。重新静止并执行 `imu zero` 会重新对准、重置初速／原点并改变 `origin_id`。
4. IMU启动后可另发 `start` 运行EEG；采集使用独立SPI2。重对准可在EEG运行时进行，但设备仍须按要求静止。实际并行采集性能尚未验证。
5. `imu stop` 停止软件采样；它不是IMU电源开关。`imu probe` 保留停采探测用途。初始化／探测时也要求IMU流停止。

USB示例（COM号按实际调整；`--align` 表示用户明确承诺保持静止）：

```powershell
python Firmware/tools/receive_motion.py --serial COM8 --start --align --eeg-output eeg.csv > motion.csv
```

工具在收到有效IMU数据后等待1秒再申请对准；请保持静止直到对准成功。若设备刚开机、时序未锁定或对准被拒，应检查 `imu status` 并重新发命令。默认不会由接收器自动发起对准。

Wi-Fi控制沿用本地口令认证；EEG数据仍到配置的9000端口，运动数据发到相同目标IP的9002端口：

```powershell
python Firmware/tools/send_eeg_command.py "imu start"
python Firmware/tools/send_eeg_command.py "imu align"
python Firmware/tools/receive_motion.py --udp 9002 > motion.csv
```

离线运动备份：

```powershell
python Firmware/tools/receive_motion.py --file imu_000001.yim > motion.csv
```

## 采样、输出和质量状态

GPIO44的DRDY中断只记单调微秒时间和边沿计数，独立任务在SPI3上读取数据。读取前取得总线，使用最新实际中断时间；检查CRC／延迟一帧的源地址、状态位、传感器数据类型、各组三轴计数一致性以及读期间是否又到DRDY。逐样本学习输出周期，连续稳定20次后才用于解算；不把decimation=32或厂家噪声测试采样率直接当成本板ODR。读延迟达到已学周期90%时拒收。计数器只有4位，遗漏数是下界，整周回卷不能单独恢复精确丢失数。

SPI3每个器件由单一任务访问；采样事务按ESP-IDF4.4接口要求取得／释放总线，显示按4行分段。最大等待和实际采样截止时间仍需测量。[Espressif SPI接口](https://docs.espressif.com/projects/esp-idf/en/v4.4/esp32s3/api-reference/peripherals/spi_master.html)

固件逐合格传感器样本解算，约50Hz输出128字节 `YIMU` v1帧。它含64位DRDY时间、独立序号、质量位、原始六轴、温度、四元数、速度／位置、原点ID、窗口年龄、读取延迟、丢样／拒收／队列计数及CRC16。`eeg_seq`／`eeg_us32` 是输出时最近已处理EEG样本的一致快照，**不是已证明的同一时刻或滤波延迟补偿**。

USB由同一个输出任务发送EEG／IMU帧，接收器按完整帧分流，避免把载荷里的魔术字误当成另一个EEG帧。旧EEG接收工具已支持跳过IMU帧；SD分别记录 `.yee`／`.yim`，存储和网络不在采样中断／IMU任务执行。输出队列、USB、UDP和SD各自记录丢弃计数。

质量位包括 `warmup`、`yaw_unreferenced`、`position_relative`、`aligning`、`align_rejected`、`sample_gap`、`window_expired`、`sensor_fault` 和 `hardware_unverified`。预热标记采用本次IMU启动后15分钟的保守提示，不能证明已经热稳定。超过250ms未发布新记录时，实时状态／屏幕不再报告有效解算；接收工具对超过0.5秒无运动记录提示陈旧数据。文件中的历史有效标记只描述其采样时刻。

协议偏移、单位与位定义见 [运动协议](REVH_MOTION_PROTOCOL.md)。本版未输出未经标定的协方差，也不把有效性位解释为精度置信区间。

## 验证和限制

软件检查覆盖实际C++解算核心、采样门限、计数回卷／重复和读延迟，以及实际编码器到Python解码器的交叉语言帧。另测试静止、已知加速度／旋转、对准拒绝、禁止自动零速、窗口到期／丢样失效、混流中嵌入完整EEG帧、分片、CRC与SD文件EOF。构建与检查数量／散列以 `firmware/build/BUILD_INFO.json` 为准，不当作硬件测试。

K01驱动基于固定版本的[参考实现](https://github.com/HTY2003/smplboards-SCH16T/tree/86e1832db6091c774741fe5eb3130e60e23a30a8)，保留BSD声明。已取得的厂家短手册只有20个物理页面；公开索引中的部分完整协议内容用于复核，完整PDF直接获取曾返回403，未绕过。厂家的Linux驱动型号表包含SCH1633，不能因此视为K01的板级验证。

样机仍须核对六面重力符号、陀螺转向、DRDY实际频率、同组三轴更新、混合QSPI／SPI方向与最坏等待，测量显示／无线／SD并行时的EEG噪声。再做温度／静止Allan、已知距离和角度的动态对照，确定可接受窗口与误差。当前没有绝对航向、持续房间定位或人体连接安全验证。
