# IMU／AMOLED SPI3 时序复核（隔离传输候选已编译）

本记录对应 `Firmware/ads1299_driver/` 和ESP32 Arduino2.0.11。ADS1299专用SPI2；IMU与显示共SPI3，各用独立片选。当前开发固件实现公共主机管理、4行显示分块、DRDY连续采样、相对姿态和静止对准后的3秒相对轨迹，并已编译通过。用户选择不部署基站；[使用范围](REVH_INDOOR_NAV.md)不包含长期位置或绝对航向保证。

SPI3使用 `driver/spi_master.h`：SCLK=8、MOSI=9、MISO／QSPI D1=14、D2=15、D3=16，显示CS=2。IMU CS=43、DRDY=44；当前PCB、原理图与开发固件已同步，不再保留这两个脚的UART0调试用途。

现有单个像素事务为 368×18×2=13248 字节，10MHz四线传输的理想数据时长约2.65ms，尚未计命令和驱动开销。200Hz IMU周期为5ms，400Hz为2.5ms，因此不能未经复核直接沿用该阻塞长度。

这里的200／400Hz是调度预算举例，**不是当前decimation=32已经确认的硬件输出率**；厂家零偏测试中的200Hz采样条件也不能推定本板DRDY频率。当前驱动逐样本学习DRDY周期、检查传感器计数及读取新鲜度；仍须在硬件确认输出率、更新相位和读数截止时间，再核定最坏显示占用预算。

当前代码将每段显示像素传输限制为最多4行：2944字节、理想数据时长约0.589ms，窗口和驱动开销另计。每个条带单独设置完整窗口并使用RAMWR。IMU任务在core0、优先级3，显示为优先级1；EEG保留独立SPI2和原采集路径。最坏事务等待、实际调度和并发采集仍需测量。

公共SPI3总线必须只初始化一次；显示故障时仅移除显示设备，不能释放仍被IMU使用的总线。CS2和CS43在启动SPI前均保持高电平。Sensor MISO与QSPI D1共线的方向切换、三态释放、显示失电后的电平转换器行为必须实测。SPI事务由驱动互斥，并确保不同设备的模式、命令位数、全／半双工及位序各自配置正确。

采样链已校验CRC、源地址、状态、数据类型、同组三轴代际、计数连续性与读期间新边沿；学习周期稳定20次后才驱动解算，读取延迟达到周期90%则拒收。取得总线前的等待也计入DRDY到读取完成的延迟。任务按所用ESP-IDF4.4接口要求使用 `portMAX_DELAY`；旧停采探测中不符合该接口的有限等待参数已修正。该API参数不构成有限最坏等待保证，实际截止时间必须测量。[官方接口](https://docs.espressif.com/projects/esp-idf/en/v4.4/esp32s3/api-reference/peripherals/spi_master.html)

FIFO／USB／UDP／SD分别统计输出丢弃；采样异常会撤销解算有效性。15分钟预热提示、任意初始航向、相对位置和未经硬件验证标记随运动帧输出，不把短时积分解释为长期定位。设备实时状态对250ms没有新发布的情况撤销有效位。

以上是由代码和线速得出的设计预算，不是已经通过硬件测量的最坏时延保证。

## 2026-11-01 驱动与软件验证

已从明确支持K01的[参考实现](https://github.com/HTY2003/smplboards-SCH16T/tree/86e1832db6091c774741fe5eb3130e60e23a30a8)移植台架驱动并合入开发固件，保留Murata与上游作者的BSD声明。它使用ESP-IDF设备句柄及硬件CS43，在共用SPI3上按2MHz、Mode0发送48位事务，保留10µs的CS高间隔；检查延迟一帧响应的CRC与源地址，传播配置／读回错误，并在没有硬复位GPIO时每次重试都发SPI复位。

`imu start` 初始化要求EEG停止；随后可并行EEG采集。`imu align`／`imu zero` 明确要求静止对准；`imu probe` 保留停采且运动流停止时的探测。DRDY ISR仅记录时间和计数，所有传感器事务由单一任务拥有，存储及网络在别的任务执行。共总线方向、电平、锁存一致性、安装轴及误差仍需实测。

当前固件在ESP32 Arduino2.0.11、16MB Flash／8MB OPI PSRAM／原生USB CDC配置编译通过：Flash809193字节、静态RAM46592字节，运行时堆／PSRAM另计。实际CRC／符号函数有固定向量、40个载荷位逐位翻转及20位边界编译检查；代际检查增加数据类型／计数位测试。36项实际C++核心／门限／编码检查、10项运动协议及6项EEG协议测试通过。8个运动／显示GPIO常量与KiCad原生引脚函数核对通过，包含TXD0=GPIO43、RXD0=GPIO44的厂家别名。来源、输入和二进制散列在 RevH `firmware/build/BUILD_INFO.json`。这些检查不验证真实芯片型号、总线或惯导性能。
